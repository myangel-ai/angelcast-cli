# angelcast CLI — Command Reference

`angelcast` makes personalized kids' podcasts from the terminal: sign a family
up, generate episodes and series, and play or download the audio.

## Install

```bash
curl -fsSL https://github.com/myangel-ai/angelcast-cli/releases/latest/download/angelcast-cli-installer.sh | sh
```

```bash
brew install myangel-ai/tap/angelcast
```

Debian and Ubuntu users can take the `.deb` from the
[latest release](https://github.com/myangel-ai/angelcast-cli/releases/latest).
macOS and Linux (x86_64 and arm64) are supported.

`angelcast --help` lists the commands, every command's `--help` ends with
example invocations, and `angelcast docs` prints the reference below offline.

## Getting started

Run `angelcast` on its own to see where to begin. A bare
`angelcast family onboard` walks you through signing up — accepting the Terms
of Use, family name, email, password, and your children — then saves your
session:

```bash
angelcast family onboard
angelcast podcast topic-suggestions
```

At a terminal, commands end with a `next:` line suggesting what to run next.
It goes to stderr and is left out of piped output and `--format json`.

Human output and `--help` are coloured when stdout is a terminal. Piped output,
`--format json`, `angelcast docs`, and any run with `NO_COLOR` set are plain
text; `CLICOLOR_FORCE=1` keeps colour when piping.

## Sessions

`family login` and `family onboard` save the session cookie they receive, so
later commands send it automatically:

```bash
angelcast family login --email you@example.com
angelcast family get
```

- Sessions live in `sessions.yml` next to `config.yml` in the angelcast config
  directory, keyed by the host you are talking to. The file is written with
  mode `0600`.
- Precedence for the cookie sent: `ANGELCAST_SESSION`, then the stored entry
  for the host. Login commands print the cookie as their first
  stdout line only when stdout is not a terminal, so `export
  ANGELCAST_SESSION="$(angelcast family login …)"` pipelines keep working while
  an interactive login shows no secret; pipe through `cat` to see it.
- The stored entry carries the cookie's `Max-Age`/`Expires`; an expired entry is
  treated as absent.
- A **401** prints `error: unauthorized for <host>: not logged in or session
  expired; run \`angelcast family login\`` and exits 1. A cookie that was
  actually sent is never deleted, so use `logout` to drop a rejected one. The
  only automatic cleanup is pruning a stored entry that had already expired
  locally (nothing was sent). `family login` and `family change-password` are
  exempt: their 401 means wrong credentials. `family login` says `wrong email
  or password`, or `This account has no password yet; contact
  support@angelq.ai to set one.` when the family has none yet.
- **Passwords never go on the command line.** `family login`,
  `family onboard`, and `family change-password` prompt with echo off (a new
  password is asked for twice), or read the password from stdin (one per line,
  in prompt order, unconfirmed) with `--password-stdin` for scripts — so
  nothing lands in `ps` or shell history.
- **Terms of Use.** `family onboard` asks you to accept the
  [Terms of Use](https://www.angelq.ai/terms-of-use) before it creates
  anything, and `family login` asks when your family hasn't accepted the
  current version. Your acceptance is kept with your account, so logging in on
  another machine doesn't ask again. Declining exits 1 without creating a
  family or saving a session. Without a terminal, pass `--accept-terms`;
  otherwise the command fails rather than waiting for an answer.
- `angelcast logout` forgets the current host's entry; `logout --all` forgets
  every host.

## Errors

Errors print to stderr as `error: <context> failed (<status>): <tag>` and exit
**1** — e.g. `error: family update failed (409 Conflict): email_in_use`. The
tag is the server's domain-error string; an untagged body is shown raw.
The one exception is the weekly usage cap (429 `weekly_limit_reached`), which
prints `error: weekly podcast limit reached (36 of 36 in the last 7 days); a
slot frees at <resets_at>` — see [Usage cap](#usage-cap).

## Usage cap

`podcast create`, `podcast create-ftue`, and every episode planned by
`series create` count against the family's 36 podcasts per rolling 7 days.
At the cap they fail with `error: weekly podcast limit reached (36 of
36 in the last 7 days); a slot frees at <resets_at>`. A family already at the
cap is rejected before the series planner runs; otherwise, if the planned
episodes don't all fit, `series create` fails after it with `error: weekly
podcast limit reached (34 of 36 in the last 7 days, this needs 5); the oldest
counted podcast leaves the window at <resets_at>` — no slot is promised, since
one episode aging out may still leave too few. Either way nothing is created.

`family usage` prints `used=<n> limit=<n> remaining=<n> resets_at=<rfc3339>`,
or `used=<n> limit=uncapped` where the server has no cap configured.
`resets_at` is when the oldest counted podcast leaves the window (omitted when
nothing is counted).
